03 · Operate

Dark carriers now get repowered overnight

Carrier-down auto-repower

Graham

A 4G or 3G carrier at 0% for the whole previous day, while its 2G is up and the site answers pings, used to stay dark: the existing ping and 2G-traffic resets saw a healthy site.

  • Runs at 06:00, one attempt per node per day
  • Repowers through the EMC on the same node's 2G cell, matched by BTS_IP, so multi-sector sites hit the right ARN
  • 4G first, then 3G; a node dark on both is cycled once

Better detection

Graham

  • Per-generation (2G/3G/4G) BSC alarms in the live alarm engine
  • Low Erlangs catches traffic collapses, not just low averages
  • Ping outages survive a monitor restart and show on Monitor Hour
  • Dual-SDR cells and the 26.01 btsmon schema supported

03 · Operate

Finding ARNs that need a USB 3 SDR

An SDR running in USB 2 mode cannot carry 3G or 4G. The fleet now finds these ARNs and makes sure the swap happens.

1 · amn-monitor

Reads the SDR's USB mode and serial from every ARN

2 · Portal

Stores it hourly and daily; in the Monitor Hour API and CSV

3 · Auto ticket

Gets a "Replace ARN (USB 2 SDR)" line naming the cell and SDR serial

4 · ACS Step 05

"ARN replaced" check fails until the FE confirms the swap

Graham · portal #547, #583 · amn-monitor #26, #28

The ticket line is re-read at creation, on a re-code and on the daily refresh, so it clears itself when a USB 3 SDR goes in. Trouble Tickets has a "Replace ARN (USB 2 SDR)" pill and filter, and the diagnostics open-ticket table has a column for it. The AI Agent and CLI guide both describe the line.

04 · Maintain

Fleet firmware upgrades from one page

Choose

  • One row per physical ARN, keyed on BTS_IP
  • Image catalogue gathered from every app server
  • Filters: hide on-target, down, master or unknown versions
  • Select the next N as a batch

Run

  • Dispatcher with a per-country concurrency gate
  • Live download progress; stalls detected and retried
  • Automatic power reset as part of the upgrade
  • Retry classifier; tasks rescued from a live snapshot

Check

  • ARN snapshot and live ping test from each row
  • Executor timeline from amn-monitor in every task
  • Pre and post version recorded; ARN list updated on success
  • Dedicated role for upgrade access

The portal side decoupled from the volatile cellMap: upgrades now carry BTS_IP and optional EMC_IP.

04 · Maintain

In-country staging and safer upgrades

In-country image staging

The portal reads the target firmware manifest from xga-manager and tells each country's amn-monitor what to stage.

amn-monitor pulls the image from a local XGA over the in-country LAN. No image bytes cross the portal or a border.

A stalled transfer resumes from the verified part instead of starting again.

Safety fixes

  • The RAN must be fully stopped before flashing, after an ARN was bricked in Zambia (MZM) on 21 July
  • An upgrade survives an amn-monitor restart mid-job
  • Portal restarts and deploys are safe mid-job
  • The image selector no longer resets on refresh, which had caused an accidental downgrade

Graham · portal #444, #445, #464, #473 · amn-monitor #8, #9, #11 and Bitbucket #63–64

Staging went live in July: the portal tells each country monitor which image to stage and where to pull it from locally, and less-preferred local sources are used only as a fallback.
