Orientation

Same job. A clearer way to do it.

ACS is the page you complete during a site visit — record your results, run the automated tests, and get a leave code that signs the site off. ACS 2.0 keeps every one of those jobs and the rules behind them. What's new is the shape of the work.

1

Guided, not scrolled

The old single long form becomes a 7-step workflow down the left. Each step shows a live ✓ / ✕ / ! so you always know what's outstanding.

2

One site, one visit

A dispatch now covers the whole site — every cell and sector — instead of one cell at a time.

3

Tests that survive the link

The automated tests run on the server, so a flaky VSAT link or a sleeping laptop no longer loses your progress.

i
The tests, the thresholds, the leave-code rules and where your data goes are all unchanged. If you knew the old ACS, you already know what's being measured — this is a new way to drive it.
The one change to remember

ACS is now completed per site — not per cell.

On the old page you completed a separate ACS for each individual cell. On a three-sector site, that was three dispatches.

ACS 2.0 does the site once. A single dispatch now covers every cell and sector, and gives you one submission and one leave code for the whole site.

!
Before you complete ACS, make sure every sector and cell on the site is working. The tests and the drive test are checked across the whole site — a dead sector will show up here.

Steps 01–03 · Getting set up

Open the site, pick the work, record the data

01

Overview

See every past dispatch for the site. Hit + New dispatch to start, or Edit the latest to carry on. A short intro reminds you the ACS is now site-level.

02

Cell selection

Choose the dispatch type and the cell in scope. The rest of the workflow stays locked until a type is chosen, so you can't skip it by accident.

03

Data & photos

Service checks, signal & power readings, engineer names, and your installation and Snyper photos — same fields you know, laid out to breathe.

✕
New: picked the wrong photo? Every thumbnail now has a small ✕ to remove it before you submit. Selecting more photos adds to the set rather than replacing it — so remove, don't re-pick.
Step 04 · The big one

Background tests run on the server

Press Initiate all background tests and confirm every sector is working. From then on the tests run on the server — move between tabs, and they keep going even if your link drops.

Each test is a card with a live status. The 15-minute BTS ping runs per sector, with its own timer and a Re-run button. Start it early — it's the longest one.

i
Expand any card to see the 60-second measurement blocks building up — ping, Es/No, C/No and the full EMC readout.

Step 04 · CCTV

The camera configures itself

There's no separate CCTV test to run any more. The CCTV card does the whole job automatically: it checks the camera, applies the standard configuration, and pulls a snapshot.

Your part is the bit only a human can do: when the snapshot loads, frame the cabinet box, then tick that the cabinet is in the box and the solar panels are visible. That pushes the intrusion region and completes the card.

Step 04 · VSAT power levels

The VSAT test knows the backhaul

You no longer decide whether the VSAT power-level test applies. ACS 2.0 reads the site's backhaul and does the right thing automatically.

✓

VSAT sites (Gilat, Hughes…)

The Es/No and C/No power-level test runs and must pass, exactly as before. Expand the card to watch both level sets build up in 60-second blocks.

–

LEO sites (Starlink, Amazon…)

There's no dish to point, so the card shows N/A and the satellite step is hidden. That's correct — not an error. The 15-minute BTS ping covers the link.

!
If a genuine VSAT site ever shows the power test as N/A, its backhaul may be recorded wrongly — flag it to GNOC rather than signing off, because the dish won't have been power-checked.
Step 06 · Satellite info

Pointing & skew — only when it matters

For dish-backhaul sites, the satellite step shows the calculated pointing and skew angle. Enter your measured skew and confirm it — it must sit within tolerance of the calculated value.

On LEO sites this whole step disappears, because there's no dish to skew.

!
If the satellite data hasn't loaded, the skew check will hold as a failure — not pass. Wait for the pointing data to appear (select a cell if needed), then enter and confirm your reading.

Step 07 · Validate & submit

The checklist, your leave code, and upload

The Validate step tallies everything: Passed / Failed / N/A. Any failure has a Fix → button that jumps you straight to the field that needs attention.

Zero failures issues a leave code automatically. If there are failures you can still submit — but the leave code will have to come from GNOC.

On submit you get an item-by-item progress list, then an outcome box confirming everything reached the ACS server — so you're never guessing whether it went through.

Six things to remember

01
Check every sector firstThe tests cover the whole site — confirm all sectors and cells are up before you start.
02
Start the BTS ping earlyIt's a 15-minute test per sector. Kick off "Initiate all" as soon as you arrive and let it run.
03
Tests survive a dropoutThey run on the server — switch tabs, lose the link, come back. Progress isn't lost.
04
CCTV is automaticJust frame the cabinet box when the snapshot loads and confirm cabinet + solar visible.
05
N/A on LEO is normalStarlink/Amazon sites show the VSAT power test as N/A — that's expected, not a fault.
06
Watch the submit outcomeThe outcome box confirms every item uploaded. If anything failed, fix it and submit again.
